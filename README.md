# JavaScript V2 — Aufgaben-Template

Dieses Template ist die Startvorlage für **jede Abgabe** im Kurs: Für jedes
Kapitel (Übungen), jedes Projekt (1–3) und das Abschlussprojekt legst du
**ein eigenes, privates Repository** an — in der GitHub-Organisation deiner Klasse.

---

## Erst mal ganz einfach: Wie das funktioniert

- **GitHub** ist ein Speicherort im Internet für Code. Wie ein Ordner, nur online.
- Ein **Repository** (kurz „Repo") ist so ein Ordner mit deinen Dateien und deren Änderungshistorie.
- Dieses Repo ist ein **Template** (Vorlage). Du machst dir davon für jede Abgabe eine eigene Kopie.
- Deine Schule hat eine **Organisation** auf GitHub (z. B. `2BFITT`). Dein Repo legst du **dort** an, nicht auf deinem privaten Account.
- **Privat** heißt: Von außen sieht niemand etwas. Deine Lehrkraft ist Eigentümerin der Organisation und sieht alle Repos **automatisch** — **niemand muss eingeladen werden**.

---

## Einmalig zu Beginn des Kurses

1. **GitHub-Account anlegen** (falls noch nicht vorhanden): Auf github.com registrieren — am besten mit deiner **Schul-E-Mail** und einem Benutzernamen, der dich erkennbar macht (z. B. Vorname + erster Buchstabe Nachname, alles klein, keine Umlaute).
2. **Einladung der Organisation annehmen:** Deine Lehrkraft lädt dich einmalig in die Klassen-Organisation ein — die Mail von GitHub mit **„Join"** bestätigen. Ohne diesen Schritt geht nichts.

---

## Für JEDE Abgabe: Repo aus dem Template anlegen (immer gleich)

1. **Diese Vorlage öffnen** und oben rechts auf den grünen Knopf **„Use this template" → „Create a new repository"** klicken.
2. **Owner richtig stellen:** Oben beim Owner deine **Klassen-Organisation** auswählen (z. B. `2BFITT`) — nicht dein privater Account.
3. **Repository-Name nach dem Schema eintragen:**
   - `jsc-kap04-17` (Übungen des Kapitels 04 — so für alle Kapitel 01–12)
   - `jsc-projekt-1-17` bis `jsc-projekt-3-17` (die drei Projekte)
   - `jsc-abschluss-17` (Abschlussprojekt)
   - Die Zahl am Ende ist **deine Nummer in der Klassenliste**. Die Klasse steht nicht im Namen — sie steckt schon in der Organisation.
   - **Ein Repo pro Abgabe:** Kapitel-Übungen, jedes Projekt und das Abschlussprojekt bekommen jeweils ein eigenes Repo.
4. **„Private"** (privat) wählen — nicht Public!
5. **„Create repository"** — fertig. Deine Lehrkraft sieht das Repo automatisch (kein Einladen nötig).
6. **Code auf deinen Rechner holen:** **Code → Download ZIP** → entpacken → in VS Code öffnen. (Wer mag: `git clone`.)

&gt; **Merke:** Die Vorlage selbst wird nie verändert. Du arbeitest ausschließlich in deinen eigenen Kopien.

---

## So arbeitest du in deinem Abgabe-Repo

1. **Die Aufgabenstellung** findest du im Tutorial: https://www.pantam.at/tutorials/js-classic-v2/
2. In der `index.html` **Titel und Überschrift** anpassen (z. B. „Kap. 04 — Übungen").
3. **Schrittweise bauen** — HTML, CSS, JavaScript sauber getrennt. JavaScript kommt mit `defer` in den Head (so wie in der Vorlage).
4. **Im Browser prüfen:** `index.html` mit der **Live-Server-Erweiterung** in VS Code öffnen.
5. **Zwischenstände sichern:** Immer wenn etwas funktioniert, **committen** („Commit changes" + kurzer Satz, was du gemacht hast) und **pushen** („Sync Changes").
6. **Screenshots** als Beleg in den Ordner `screenshots/` legen (z. B. „handy-test.png").
7. **Fertig?** Sag deiner Lehrkraft den **Repo-Namen** (z. B. `jsc-kap04-17`) — sie findet alles über die Org-Suche. Abgegeben ist nur, was **gepusht** ist.

---

## Was ist mit dem Veröffentlichen (GitHub Pages)?

Private Repositories kann man im kostenlosen Tarif **nicht** öffentlich über GitHub Pages veröffentlichen. Deine Lehrkraft sieht dein Ergebnis direkt im Repo — das reicht fürs Beurteilen. Falls du ein Projekt zusätzlich öffentlich zeigen willst, sprich das mit deiner Lehrkraft ab.

---

## Gute Gewohnheiten

- **Ein Repo pro Abgabe** — nie mehrere Kapitel oder Projekte in einem Repo mischen.
- Ordner- und Dateinamen klein, mit Bindestrichen: `screenshots/handy-test.png`, nicht `Screenshots/Handy Test!`.
- Keine fremden Bilder ohne Quellenangabe, keine personenbezogenen Daten.
- **Regelmäßig committen und pushen** — kleine, funktionierende Zwischenstände schlagen seltene Groß-Commits.
- Teste am Handy (Browser-Entwicklerwerkzeuge → Geräte-Emulation, 360 px).
